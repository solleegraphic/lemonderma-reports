영상 프롬프트 길이 리서치

Sol · 2026-09-28 · 시댄스(Seedance) 영상 프롬프트 — "짧아야 잘 나온다"는 말을 실측으로 점검

결론 한 줄: "프롬프트가 길어서 결과가 나쁘다"는 절반만 맞다. 시댄스는 길다고 글자를 잘라 무시하지 않는다 — 진짜 원인은 길어질수록 지시들이 서로 관심(어텐션)을 나눠 먹는 것이다. 그리고 그보다 더 확실한 문제 두 가지를 찾았다: 우리가 매번 붙이는 "Negative prompt" 블록이 애초에 작동하는 채널이 아니었고, 제작 도구가 이미 지원하는 구조화 멀티샷 기능을 안 쓰고 있었다.

① 가장 먼저 확인한 사실 — 우리 도구 스펙 등급 A

외부 가이드를 찾기 전에, 우리가 실제로 호출하는 Magnific video_generate 도구의 스펙을 직접 열어봤다. 이건 외부 블로그보다 신뢰도가 높다 — 우리가 실제로 쓰는 API 계약 그 자체이기 때문이다.

도구 설명 자체가 "네거티브 프롬프트는 모델이 지원할 때만 쓴다"고 적혀 있는데, 시댄스 계열 6개 전부 이 필드가 카탈로그에 없다. 즉 우리가 매번 프롬프트 끝에 붙이는 Negative prompt: hand, finger, circle... 블록은 별도 채널이 아니라 같은 10,000자 예산 안의 그냥 텍스트다.

또 하나: multi_prompt라는 필드로 샷마다 별도 프롬프트·길이를 가진 구조화 멀티샷(최대 6샷)이 이미 지원된다. 우리는 지금까지 이걸 안 쓰고 0.00-3.00s / 3.00-8.00s...처럼 하나의 문자열 안에 타임코드를 박아 넣는 방식만 써왔다.

④ 네거티브 프롬프트, 실제로 작동하는가? 확정 문제

없다. 우리 관행이 안티패턴에 가깝다.

🔴 지금 우리가 하는 것

편당 1,000~1,800자짜리 "Negative prompt:" 벽을 매번 만들어 붙인다. hand, finger, circle, round loop, oval, letter O... 수십 개 나열.

우리 자신의 실측과도 들어맞는다 — 네거티브에 맨 단어 hand를 넣으면 손이 통째로 사라지는 현상이 있었다. 진짜 negative 채널이었다면 "그 속성만 안 나옴"이어야 하는데, "통째로 사라짐"은 그냥 본문 어딘가에 hand 토큰이 하나 더 늘어서 생긴 부작용으로 설명된다.

⑤ 참조 이미지가 있으면 외형을 다시 서술해야 하나? 확정 문제

아니다 — 반복하지 말라는 게 정본이다.

"Don't repeat 'a woman in a red dress' if she's already in the photo — say what she does." 참조에 이미 있는 걸 다시 문단으로 쓰고 있다면 지우고 참조를 가리켜라.
seedance.tv · 등급 B

우리 UGC 프롬프트 서두("a young woman with curly blonde hair tied up, small hoop earrings...")는 레퍼런스 이미지가 이미 고정하는 외형을 다시 문장으로 그리는 패턴이다 — 이 구간이 그대로 낭비되는 글자 수일 가능성이 높다.

⑥ 타임코드·멀티샷 구조 여지 있음

Seedance 2.5는 초 단위 타임스탬프를 잘 따른다는 게 공식계열 가이드 주장(등급 B)이지만, 동시에 2.0 종합 스킬(등급 C)은 "엄격한 타이밍은 불안정할 수 있으므로 샷 순서 우선"이라고 경고한다 — 완전히 일치하진 않는다.

결정적인 건 ①에서 찾은 1차 소스다: Magnific은 multi_prompt라는 구조화 멀티샷을 이미 지원한다(최대 6샷, 샷별 duration). 지금 우리는 이 기능을 안 쓰고 모든 걸 하나의 prompt 문자열에 타임코드로 욱여넣는다 — 26초 UGC물은 시점 10구간(중앙값)인데, 이건 멀티샷 한도(6샷)를 이미 넘는다.

개선 원칙 5가지

  1. 네거티브 블록을 없애거나 대폭 줄인다. Seedance는 negativePrompt 필드가 없다 — "Negative prompt:" 벽 대신, 정말 지켜야 할 3-5개 항목(정체성·제품 형태·손가락 개수 등)만 본문 안에 "avoid X" 형태로 녹인다. 자막·오디오 억제("no subtitles", "no music")만 순수 부정형으로 남긴다.
  2. 참조 이미지가 고정하는 외형은 재서술하지 않는다. 인물·제품 생김새는 레퍼런스에 맡기고, 프롬프트는 동작·카메라·타이밍만 쓴다.
  3. 26초 이상 멀티세그먼트 영상은 Magnific multi_prompt(최대 6샷) 사용을 우선 검토한다. 한 세그먼트가 6개를 넘어야 하면 씬을 더 큰 단위로 합치거나 생성을 나누는 걸 먼저 고려.
  4. LOCK/=failed 절은 "정말 사고가 난 항목"만 남긴다. 같은 제약의 동의어 반복은 병합.
  5. 압축이 필요할 땐 총 단어수보다 "구조 4단계"가 살아있는가를 기준으로 판단한다. 자산참조 → 한줄요약 → 세그먼트 플롯 → 마감제약. 무작정 문장을 쳐내면 오히려 구조가 깨져 정보 유실이 난다.

적용 순서 제안: 다음 신규 편부터 1~3원칙을 시범 적용 → 결과 비교(같은 씬, 네거티브 有/無 A-B) → 차이가 확인되면 brand-prompt-dna.md LOCK 섹션에 정식 반영.
